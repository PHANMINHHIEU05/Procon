# M8.2.1 `/state.others` Live Value Probe

## Live evidence

Practice match `m-2389` returned the following structure on days 0 through 3:

```text
ARRAY[
  OBJECT{
    agents:ARRAY[
      OBJECT{fuel:NUMBER,kind:NUMBER,pos:NUMBER}
    ],
    id:NUMBER
  }
]
```

The response contained three outer entries, matching the three other teams in
the match. This is live protocol evidence for the field names and nesting.

## Typed parsing

The protocol module now provides neutral records:

- `ObservedOtherGroup(int rawId, List<ObservedOtherAgent> agents)`
- `ObservedOtherAgent(Position position, int rawKind, int fuel)`

`ObservedOthersParser` reads the existing raw `JsonNode` without changing
`DayStateDto`. It accepts only integral values representable as Java `int`,
matching the existing protocol numeric safety convention. Groups are sorted by
`rawId`; agent array order is retained only within the current observation.

Malformed groups and malformed individual agents are skipped. Unknown fields
are ignored. Missing, null, empty, or non-array `others` values produce an
empty observation and do not affect normal state mapping or match execution.

### OBSERVED

- `others` is an array of outer objects.
- Each live outer object has `id` and `agents` fields.
- `agents` is an array of objects with `pos`, `kind`, and `fuel` fields.
- The live match returned three outer entries on days 0 through 3.
- Raw numeric values can be retained and compared descriptively.

### SUPPORTED INFERENCE

- Sorting outer entries by `rawId` gives deterministic diagnostics.
- Comparing raw-ID sets and per-raw-ID agent counts is safe group-level
  observability.
- Comparing position sets for one `rawId` across days can show that observed
  positions changed, without identifying which agent moved.
- The observed `pos` values can be checked against the setup map's flat cell
  range.

### UNKNOWN

- Whether `rawId` is a team ID or another identifier.
- Whether `rawKind` uses the own-agent encoding.
- Whether `rawKind=0` or `rawKind=1` means PATROL, REFUEL, or something else.
- Whether an agent's list index is stable across days.
- Whether `fuel` is current fuel, a different numeric quantity, or subject to
  the own PATROL capacity/rules.
- Whether an observed agent can move, collect, refuel, or be matched across
  days without an explicit agent ID.

No typed field is promoted to `teamId`, `AgentKind`, ETA, movement capability,
fuel consumption, or agent identity.

## Diagnostics

The existing shape flag remains independent:

```text
PROCON_OTHERS_SHAPE_DIAGNOSTICS=true
```

The value flag is separately opt-in:

```text
PROCON_OTHERS_VALUE_DIAGNOSTICS=true
```

Example value output:

```text
OTHERS_VALUES matchId=m-2389 day=0 group=0 rawId=12 agents=2 values=[{index=0,pos=31,rawKind=0,fuel=47,positionValid=true,withinOwnPatrolFuelRange=true}]
OTHERS_KIND_VALUES matchId=m-2389 day=0 values=[0, 1] truncated=false
OTHERS_STABILITY matchId=m-2389 day=1 outerCount=3 sameRawIdsAsPrevious=true sameAgentCountsByRawId=true
OTHERS_POSITION_CHANGE matchId=m-2389 day=1 rawId=12 previousPositions=[31] currentPositions=[32] changed=true
```

The runtime logs at most three groups, four agents per group, sixteen distinct
raw-kind values, and four positions per group. It never emits raw JSON,
unknown fields, request bodies, headers, authorization values, or tokens.

`index` is a display index for one response only. It is never used as a
cross-day identity.

## Planning boundary

No opponent data is added to `DayState`. `WAIT`, `BASELINE`, `BRAND_AWARE`,
`REFUEL_AWARE`, `REFUEL_PROBE`, `TEAM_COORDINATED`, `ANYTIME`, and
`ANYTIME_HARVEST` retain their existing behavior. No contention analyzer,
opponent routing, search penalty, collection prediction, or M9 behavior is
implemented.

The next and only recommended gate is `M8.2.1 LIVE VALUE PROBE` review. Further
semantic promotion requires additional authoritative evidence, especially an
agent identity field and confirmed kind/fuel semantics.
